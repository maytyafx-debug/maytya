# قالب مادر صفحات قابلیت‌های مشترک METATYA

وضعیت: نسخه اولیه اجرایی و قابل آزمون  
نمونه زنده کد: `docs/shared-capabilities.html`  
قالب خام: `docs/design-system/shared-capability-page-template.html`  
فناوری: HTML، CSS و JavaScript بومی؛ بدون فریم‌ورک یا وابستگی زمان اجرا

## هدف
این سیستم برای صفحات معرفی قابلیت‌ها، استانداردها، زیرساخت‌ها و سرویس‌های مشترک اکوسیستم METATYA است. صفحه‌های جدید باید از هویت بصری و اجزای مشترک استفاده کنند؛ محتوا و بخش‌های تخصصی هر صفحه مستقل باقی می‌ماند.

## فایل‌های مشترک
- `docs/metatya-core.css`: توکن‌ها و اجزای پایه موجود برند.
- `docs/metatya-shared-pages.css`: الگوهای قابل استفاده مجدد برای Hero، بخش‌ها، کارت‌ها، نوار معماری، جریان مراحل، مرزبندی ماژول‌ها، CTA و ناوبری موبایل.
- `docs/metatya-shared-pages.js`: رفتارهای مشترک برای منوی موبایل و reveal با رعایت reduced-motion.
- `docs/design-system/shared-capability-page-template.html`: اسکلت خام صفحه برای شروع صفحه جدید.
- `docs/shared-capabilities.html`: نمونه واقعی استفاده از قالب.
- `scripts/test-shared-pages.mjs`: تست ایستا برای ساختار صفحه، لینک‌ها، شناسه‌ها و دسترس‌پذیری پایه.
- `.github/workflows/shared-pages-quality.yml`: اجرای خودکار تست در push/PR.

## روش ساخت صفحه جدید
1. فایل قالب HTML را کپی کن و نام/metadata/عنوان را جایگزین کن.
2. CSS مشترک و JS مشترک را لینک کن؛ آن‌ها را در صفحه جدید کپی نکن.
3. از کلاس‌های `mt-shared-*` برای Hero، کارت‌ها، بخش‌ها و CTA استفاده کن.
4. شناسه‌های یکتا برای بخش‌ها تعریف کن و لینک‌های منو را با همان شناسه‌ها هماهنگ کن.
5. محتوای صفحه را متناسب با قابلیت موردنظر بنویس؛ اجزای تخصصی صنعت را وارد هسته عمومی نکن.
6. تست را با `node scripts/test-shared-pages.mjs` اجرا کن. برای صفحه جدید، مسیر فایل و آزمون‌های مرتبط را به اسکریپت اضافه کن.
7. قبل از ادغام، ظاهر را در موبایل و دسکتاپ بررسی کن و لینک‌ها را دستی بازبینی کن.

## قواعد معماری
1. قابلیت مشترک فقط در لایه مناسب ساخته و نسخه‌بندی می‌شود؛ محصولات از طریق قراردادهای مشخص استفاده می‌کنند.
2. داده، دسترسی و تنظیمات هر سازمان/مستأجر مستقل می‌ماند؛ اشتراک کد به معنی اشتراک داده نیست.
3. منطق و تجربه تخصصی صنعت‌ها مستقل است؛ مدیریت ورزشکار با مدیریت مشتری سالن زیبایی یکسان‌سازی نمی‌شود.
4. از ادعای قابلیت فعال، عملکرد، مشتری، آمار یا نتیجه‌ای که شواهد ندارد خودداری شود.
5. هر لینک و دکمه باید مقصد واقعی داشته باشد.
6. صفحه باید RTL، mobile-first، قابل استفاده با صفحه‌کلید و سازگار با reduced-motion باشد.
7. اسرار، کلیدها و داده شخصی نباید در کد عمومی یا گزارش تست ظاهر شوند.

## اصل نهایی
**Build Once, Reuse Everywhere:** هر قابلیت مشترک فقط یک‌بار در لایه مناسب طراحی و پیاده‌سازی می‌شود؛ محصولات از طریق قراردادهای مشخص استفاده می‌کنند و منطق، تجربه و داده‌های تخصصی خود را مستقل نگه می‌دارند.
