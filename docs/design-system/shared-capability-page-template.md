# قالب مادر صفحات قابلیت‌های مشترک METATYA

وضعیت: نسخه اولیه اجرایی  
مسیر نمونه: `docs/shared-capabilities.html`  
فناوری: HTML، CSS و JavaScript بومی؛ بدون فریم‌ورک یا وابستگی زمان اجرا

## هدف
این قالب برای صفحات معرفی قابلیت‌ها، استانداردها، زیرساخت‌ها و سرویس‌های مشترک اکوسیستم METATYA است. هر صفحه جدید باید از هویت بصری و اجزای مشترک استفاده کند، اما ساختار محتوا را با هدف همان صفحه تطبیق دهد.

## فایل‌های مشترک
- `metatya-core.css`: توکن‌ها و اجزای پایه موجود برند.
- `metatya-shared-pages.css`: الگوهای قابل استفاده مجدد برای Hero، بخش‌ها، کارت‌ها، نوار معماری، جریان مراحل، مرزبندی ماژول‌ها و CTA.
- `metatya-shared-pages.js`: رفتارهای کوچک و مشترک برای منوی موبایل و reveal با رعایت reduced-motion.
- `shared-capabilities.html`: نمونه پیاده‌سازی واقعی قالب.

## قواعد استفاده مجدد
1. فایل CSS و JS مشترک را در صفحه جدید لینک کن؛ کپی و تکثیر نکن.
2. از کلاس‌های `mt-shared-*` برای اجزای این سیستم استفاده کن.
3. متن، شناسه بخش‌ها، کارت‌ها و CTA را متناسب با موضوع صفحه جایگزین کن.
4. از ادعای قابلیت فعال، عملکرد، مشتری، آمار یا نتیجه‌ای که شواهد ندارد خودداری کن.
5. قابلیت‌های مشترک را از ماژول‌های تخصصی صنعت جدا نگه دار.
6. داده و دسترسی هر سازمان/مستأجر مستقل بماند؛ اشتراک کد به معنی اشتراک داده نیست.
7. هر لینک و دکمه باید مقصد واقعی داشته باشد.
8. صفحه باید RTL، mobile-first، قابل استفاده با صفحه‌کلید و سازگار با reduced-motion باشد.

## اصل معماری
Build Once, Reuse Everywhere: قابلیت مشترک فقط یک‌بار در لایه مناسب طراحی و پیاده‌سازی می‌شود؛ محصولات از طریق قراردادهای مشخص استفاده می‌کنند و منطق، تجربه و داده‌های تخصصی خود را مستقل نگه می‌دارند.
